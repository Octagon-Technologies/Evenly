Notes

Recommendation: A1. It changes the least code (move one composable, add a Spacer) and fixes the order problem you described: the receipt is the thing that fills the fields, so it belongs before them. A2 is louder but duplicates the restaurant-bill hero almost exactly, so the two paths would look the same at first glance. B1/B2 add emphasis but still ask people to type Title and pick Category before they reach the thing that would have done it for them.

The popup. The quick read today returns a summary (merchant, kind, total), not line items. "Split by item" needs the full itemized scan, so either the quick read starts returning a line count (to decide when to ask), and picking "By item" runs the full scan on the same image without re-picking it, or we ask on VenueKind.RESTAURANT/CAFE/BAR alone. I'd show it only for those kinds, never for grocery or store receipts, and only once per expense.

One thing to confirm. You mentioned the read counting toward a tier limit, even on the paid plan. ui/AGENTS.md currently says receipt scans are unlimited and free with no meter, so these mocks show no limit copy. If that changed, tell me and I'll add it.
