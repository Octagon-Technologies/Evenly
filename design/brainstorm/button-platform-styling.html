Button styling: Android vs iOS

The OTP screen's "Verify & sign in" uses EvButton's default Primary: a white chip with a 1px hairline and a 1dp Modifier.shadow. On iOS, Compose draws that shadow as a hard grey rim under the hairline, which is the odd elevation you noticed. Neither platform's guidelines put a shadow on a primary button. Press and hold any button below to see its pressed state.

If you want to keep the white chip

The white chip is a deliberate design/ choice. Each platform has an official lower-emphasis style that keeps that look without a shadow: Material's Outlined button and iOS's gray (bordered) button. Both guidelines reserve these for a secondary action, though, so a lone hero CTA usually takes the filled style.

Android. M3 Outlined: hairline only, transparent fill, elevation 0.
iOS. Bordered (gray): tinted fill, no border, no shadow.

What it would take in code

1. Drop every shadow from EvButton. Delete BtnStyle.elevation and the Modifier.shadow line. That fixes the odd rim on its own, even before any restyle.

2. Make Primary the filled style on both OSes. It already is in dark mode, so this only changes light mode.

3. Branch shape, height and label per platform through the existing isIOS(), the same way EvSheetChrome already does for sheets.

private val ios = isIOS()
val height = when { small -> 36.dp; ios -> 50.dp; else -> 40.dp }
val shape  = CircleShape                       // M3 round = iOS capsule
val label  = if (ios) 17.sp to FontWeight.SemiBold else 14.sp to FontWeight.Medium
// Android: InteractionSource -> 10% onAccent overlay + corner morph to 8.dp
// iOS:     pressed -> darken fill (Color.Black 18% overlay)
