Every button, every state

The plan: filled buttons on both OSes, with no shadow anywhere except Android's floating action button, where Material 3 gives it one on purpose. Each row is one kind of button in the app. Columns follow your three states. Rest is untouched. Pressing is a finger down. Pressed is just after the finger lifts. For buttons that wait on the network, that's the busy state. For instant ones, the button is already back at rest while the next screen opens. Press and hold any button to try it live.

Notes before building

Busy state replaces the swap-to-spinner. Today the OTP screen swaps the button for a bare EvSpinner, so the button disappears. The HIG recommends a spinner inside the button with an "-ing" label. I'd do the same on Android and give EvButton a loading flag. The button stays blue (busy, not disabled) and ignores taps while loading.

Disabled stays rare. House rule: keep buttons live and explain on tap. Where a button really is disabled, Material uses on-surface at 12% for the container and 38% for the label. iOS uses the system's dimmed gray.

Red fill contrast. White on #E0686B is about 3.1:1. That passes Material's 3:1 for buttons but is under 4.5:1 for text. A slightly deeper red for the filled confirm only would fix it.

One isIOS() branch in EvButton covers height, label size and the pressed effect. Shape is a capsule on both. The FAB shadow is Android-only.
